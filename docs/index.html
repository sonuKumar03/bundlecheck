The Problem

Why Angular Bundles Grow Out of Control

Modern Angular applications use esbuild for blazing fast build times, but bundle size regressions remain a major source of slow Time-to-Interactive (TTI) and First Contentful Paint (FCP).

1

Accidental Entry Point Leaks

Importing a single utility function from a non-tree-shakeable CommonJS library (like lodash or moment) pulls megabytes directly into main.js.

2

Duplicate Nested Dependencies

Conflicting transitive versions of packages like tslib or rxjs get bundled simultaneously without developer awareness, bloating chunk payloads.

3

Zero CI Visibility & Gating

Pull requests merge unnoticed size spikes because standard CI logs bury massive JSON outputs instead of surfacing clear byte deltas and failing budgets.

Quick Setup

Installation

Install the prebuilt binary directly to /usr/local/bin (or specify --bin-dir ~/.local/bin).

$ curl -fsSL https://raw.githubusercontent.com/sonuKumar03/bundlecheck/main/install.sh | sh
# Install binary + AI Agent Skill:
$ curl -fsSL https://raw.githubusercontent.com/sonuKumar03/bundlecheck/main/install.sh | sh -s -- --with-skill

Quickstart

Generate Angular stats during your build and run bundlecheck in two simple steps:

Step 1: Build Angular with stats-json
ng build --stats-json
This produces dist/<project-name>/stats.json.
Step 2: Inspect Bundle Breakdown
bundlecheck summary dist/my-app/stats.json
Command Reference

5 Core Commands to Inspect & Control Bundles

Each command outputs clean, structured ANSI tables and trees designed for both human terminal inspection and automated CI pipelines.

1

bundlecheck summary <stats.json>

Breakdown

Parses initial entry points, lazy route chunks, and calculates total NPM package contributions sorted by byte weight.

$ bundlecheck summary dist/my-app/stats.json
BUNDLE SUMMARY
-------------------------------------------------------------
Initial JavaScript: 248.50 KB (3 files: main, polyfills, styles)
Lazy Chunks: 812.20 KB (14 route-split chunks)
Total Assets: 1.06 MB
TOP CONTRIBUTING NPM PACKAGES
-------------------------------------------------------------
1. @angular/core 84.20 KB (33.8% of initial)
2. rxjs 42.10 KB (16.9% of initial)
3. @angular/common 31.50 KB (12.6% of initial)
4. lodash-es 18.40 KB (7.4% of initial)
5. tslib 6.20 KB (2.5% of initial)
2

bundlecheck why <stats.json> <package-name>

Trace Chain

Traces the exact import graph path showing why a particular npm package was bundled, which application file pulled it in, and which chunk it landed inside.

$ bundlecheck why dist/my-app/stats.json lodash-es
IMPORT CHAIN TRACE: 'lodash-es' (18.40 KB)
-------------------------------------------------------------
src/main.ts
└── src/app/app.config.ts
└── src/app/services/analytics.service.ts
└── node_modules/lodash-es/debounce.js [in chunk: main-C82D.js]
✓ Direct dependency. Package enters through the initial entry point.
3

bundlecheck suggest <stats.json>

Optimization

Scans for heavy legacy libraries (moment, lodash), duplicate bundled package versions, and non-tree-shakeable dependencies with actionable refactoring advice.

$ bundlecheck suggest dist/my-app/stats.json
[!] 3 OPTIMIZATION OPPORTUNITIES DETECTED
-------------------------------------------------------------
• moment (72.4 KB): Found in initial bundle. Replace with native Intl.DateTimeFormat (-65 KB).
• lodash (54.1 KB): CommonJS build detected. Replace with lodash-es to enable tree-shaking.
• Duplicate package 'tslib': Bundled versions v2.4.0 and v2.6.2 simultaneously. Deduplicate in package.json.
4

bundlecheck baseline [save | list | use | rebuild | show | delete]

Worktree & Snapshots

Capture, manage, and inspect baseline bundle metrics from local builds or git branches (using isolated worktrees without branch-switching).

$ bundlecheck baseline save --ref release/v2.0 --name release-v2
Checking out git ref "release/v2.0" in temporary worktree...
Building "release/v2.0" in worktree (npm run build)...
✓ Successfully captured and saved baseline to .bundlecheck/baselines/release-v2.json
$ bundlecheck baseline list
Saved Baselines (.bundlecheck/baselines/):
NAME REF / SOURCE INITIAL JS TOTAL JS CREATED STATUS
* release-v2 release/v2.0 (43eb721) 1.42 MB 4.52 MB just now ✓ active
main origin/main (a10c82f) 1.40 MB 4.48 MB 1 day ago
5

bundlecheck measure [-b baseline-name]

Live Delta Benchmarking

Measures current working branch changes against the active or named baseline with instant byte deltas and regression budget verification.

$ bundlecheck measure
MEASURING AGAINST ACTIVE BASELINE (release-v2)
-------------------------------------------------------------
Initial JavaScript: 1.42 MB -> 1.18 MB (-240.00 KB / -16.9%) 📉
Lazy Chunks: 3.10 MB -> 2.95 MB (-150.00 KB / -4.8%) 📉
Total Bundle Size: 4.52 MB -> 4.13 MB (-390.00 KB / -8.6%) 🎉
6

bundlecheck compare <baseline.json> <stats.json>

JSON File Diff

Calculates exact byte and percentage deltas between two exported JSON snapshot summary files.

$ bundlecheck compare .bundlecheck/baseline.json dist/my-app/stats.json
BRANCH DELTA COMPARISON
-------------------------------------------------------------
Initial JavaScript: 248.50 KB -> 232.10 KB (-16.40 KB / -6.6%) ✓
Lazy Chunks: 812.20 KB -> 808.50 KB (-3.70 KB / -0.4%) ✓
Total Bundle Size: 1.06 MB -> 1.04 MB (-20.10 KB / -1.8%) ✓
7

bundlecheck check <stats.json> [flags]

CI Gate

Enforces strict size budgets. Returns exit code 0 on pass, or exit code 1 with budget violation details to block oversized pull requests.

$ bundlecheck check dist/my-app/stats.json --max-initial=300
✓ BUDGET CHECK PASSED: Initial JS is 248.50 KB (budget: 300.00 KB)
$ bundlecheck check dist/my-app/stats.json --max-initial=200
✗ BUDGET CHECK FAILED: Initial JS is 248.50 KB (budget: 200.00 KB, exceeded by +48.50 KB)
Process exited with status code 1. Pipeline failed.

Configuration (.bundlecheck.yml)

Persist project-wide size budgets and optimization rules in your repository root: 

# .bundlecheck.yml
budgets:
  initial_js_max: 250kb
  total_max: 1.5mb
  max_delta_increase: 50kb

rules:
  disallow_packages:
    - moment
    - lodash
  warn_duplicates: true

GitHub Actions Integration

Drop bundlecheck directly into your GitHub Actions workflow to post automated PR comments with delta summaries and fail oversized changes: 

name: Bundle Size Budget Check
on: [pull_request]

jobs:
  bundlecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      
      - run: npm ci
      - run: npx ng build --stats-json
      
      - name: Run bundlecheck CI
        uses: sonuKumar03/bundlecheck@v1
        with:
          stats-path: dist/my-app/stats.json
          max-initial: '250kb'
          post-comment: true
