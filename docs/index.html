The Problem

Why Angular Bundles Grow Out of Control

Modern Angular applications use esbuild for blazing fast build times, but bundle size regressions remain a major source of slow Time-to-Interactive (TTI) and First Contentful Paint (FCP).

1

Accidental Entry Point Leaks

Importing a single utility function from a non-tree-shakeable CommonJS library (like lodash or moment) pulls megabytes directly into main.js.

2

Duplicate Nested Dependencies

Conflicting transitive versions of packages like tslib or rxjs get bundled simultaneously without developer awareness, bloating chunk payloads.

3

Zero CI Visibility & Gating

Pull requests merge unnoticed size spikes because standard CI logs bury massive JSON outputs instead of surfacing clear byte deltas and failing budgets.

Quick Setup

Installation

Install the self-contained binary with zero runtime dependencies directly to /usr/local/bin (or specify --bin-dir ~/.local/bin).

$ curl -fsSL https://raw.githubusercontent.com/sonuKumar03/bundlecheck/master/install.sh | sh
# Install binary + AI Agent Skill:
$ curl -fsSL https://raw.githubusercontent.com/sonuKumar03/bundlecheck/master/install.sh | sh -s -- --with-skill

Quickstart

Generate Angular stats during your build and run bundlecheck in two simple steps:

Step 1: Build Angular with stats-json
ng build --stats-json
This produces dist/<project-name>/stats.json.
Step 2: Inspect Bundle Breakdown
bundlecheck summary dist/my-app/stats.json
Command Reference

Core Commands to Inspect, Benchmark & Control Bundles

Each command outputs clean, structured ANSI tables and trees designed for both human terminal inspection and automated CI pipelines.

1

bundlecheck summary <stats.json> [--entry <source-or-glob>]

Breakdown

Parses initial entry points, lazy route chunks, and calculates total NPM package contributions sorted by byte weight. Use --entry / -e (e.g. source path src/main.ts or emitted chunk glob main-*.js / worker.js) to scope analysis to a specific entrypoint.

💡 Entrypoint Scoping & TotalJS Invariant: --entry / -e scopes initial versus lazy reachability, package attribution, and root traces strictly to the selected entrypoint. The overall TotalJS metric consistently reflects the whole browser build across all chunks.

$ bundlecheck summary dist/my-app/stats.json
BUNDLE SUMMARY
-------------------------------------------------------------
Initial JavaScript: 248.50 KB (3 files: main, polyfills, styles)
Lazy Chunks: 812.20 KB (14 route-split chunks)
Total Assets: 1.06 MB
TOP CONTRIBUTING NPM PACKAGES
-------------------------------------------------------------
1. @angular/core 84.20 KB (33.8% of initial)
2. rxjs 42.10 KB (16.9% of initial)
3. @angular/common 31.50 KB (12.6% of initial)
4. lodash-es 18.40 KB (7.4% of initial)
5. tslib 6.20 KB (2.5% of initial)
# Scoped to entrypoint:
$ bundlecheck summary dist/my-app/stats.json --entry src/main.ts
$ bundlecheck summary dist/my-app/stats.json -e "main-*.js"
2

bundlecheck inspect <chunk.js> [--stats <stats.json>] [--dist <dir>]

Chunk Breakdown

Deep-dives into a specific emitted JavaScript chunk or route bundle, attributing exact byte weights to participating source files and npm packages.

$ bundlecheck inspect chunk-ABC123.js --stats dist/my-app/stats.json
CHUNK INSPECTION: chunk-ABC123.js (215.40 KB)
-------------------------------------------------------------
1. @angular/forms 92.40 KB (42.9% of chunk)
2. src/app/features/ 68.20 KB (31.7% of chunk)
3. rxjs/operators 34.10 KB (15.8% of chunk)
4. tslib 4.20 KB (1.9% of chunk)
3

bundlecheck why <stats.json> <package-name> [--entry <entry>]

Trace Chain

Traces the exact import graph path showing why a particular npm package was bundled, which application file pulled it in, and which chunk it landed inside. Use --entry / -e (e.g. src/main.ts or main-*.js) to scope traces to a specific root entrypoint.

$ bundlecheck why dist/my-app/stats.json lodash-es --entry src/main.ts
IMPORT CHAIN TRACE: 'lodash-es' (18.40 KB)
-------------------------------------------------------------
src/main.ts
└── src/app/app.config.ts
└── src/app/services/analytics.service.ts
└── node_modules/lodash-es/debounce.js [in chunk: main-C82D.js]
✓ Direct dependency. Package enters through the initial entry point.
4

bundlecheck suggest <stats.json>

Optimization

Scans for heavy legacy libraries (moment, lodash), duplicate bundled package copies, and non-tree-shakeable dependencies with actionable refactoring advice.

$ bundlecheck suggest dist/my-app/stats.json
[!] 3 OPTIMIZATION OPPORTUNITIES DETECTED
-------------------------------------------------------------
• moment (72.4 KB): Found in initial bundle. Replace with native Intl.DateTimeFormat (-65 KB).
• lodash (54.1 KB): CommonJS build detected. Replace with lodash-es to enable tree-shaking.
• Duplicate package 'tslib': Multiple distinct installed copies contribute to initial JS. Run npm dedupe.
5

bundlecheck baseline [save | list | use | rebuild | show | delete]

Worktree & Snapshots

Capture, manage, and inspect baseline bundle metrics from local builds or git branches (using isolated worktrees without branch-switching).

$ bundlecheck baseline save --ref release/v2.0 --name release-v2

Building "release/v2.0" in worktree (npm run build)...
✓ Successfully captured and saved baseline to .bundlecheck/baselines/release-v2.json
$ bundlecheck baseline list

* release-v2 release/v2.0 (43eb721) 1.42 MB 4.52 MB just now ✓ active

bundlecheck measure [-b baseline-name]

Live Delta Benchmarking

Measures current working branch changes against the active or named baseline with instant byte deltas and regression budget verification.

-------------------------------------------------------------

Lazy Chunks: 3.10 MB -> 2.95 MB (-150.00 KB / -4.8%) 📉
Total Bundle Size: 4.52 MB -> 4.13 MB (-390.00 KB / -8.6%) 🎉

bundlecheck compare <baseline.json> <stats.json>

JSON File Diff

-------------------------------------------------------------

Lazy Chunks: 812.20 KB -> 808.50 KB (-3.70 KB / -0.4%) ✓
Total Bundle Size: 1.06 MB -> 1.04 MB (-20.10 KB / -1.8%) ✓
8

bundlecheck check <stats.json> [--entry <entry>] [flags]

CI Gate

Enforces strict size budgets. Returns exit code 0 on pass, or exit code 1 with budget violation details to block oversized pull requests. Budgets can be scoped to specific entrypoints via --entry / -e (e.g. src/main.ts or worker.js).

$ bundlecheck check dist/my-app/stats.json --entry src/main.ts --max-initial=300KB
✓ BUDGET CHECK PASSED: Initial JS is 248.50 KB (budget: 300.00 KB)
$ bundlecheck check dist/my-app/stats.json --max-initial=200KB
✗ BUDGET CHECK FAILED: Initial JS is 248.50 KB (budget: 200.00 KB, exceeded by +48.50 KB)
Process exited with status code 1. Pipeline failed.
9

bundlecheck init [path] [flags]

Assisted Setup

Generates or previews a reviewable .bundlecheck.yml configuration with headroom over measured sizes or imported from Angular budgets. Refuses to overwrite existing configs.

$ bundlecheck init --headroom 10
# Proposed configuration with 10.0% headroom:
# Measured: Initial JS 248.50 KB, Total JS 1.06 MB
# Proposed: initial_js_max: 274KB, total_max: 1.17MB
budgets:
initial_js_max: 274KB
total_max: 1.17MB

bundlecheck workspace summary [--projects <names>]

Nx Monorepo

Aggregates existing Angular builds across an Nx workspace to compare multi-app sizes, shared library costs, duplicate dependencies, and artifact freshness.

$ bundlecheck workspace summary
WORKSPACE APPLICATION SUMMARY
-------------------------------------------------------------
• admin-dashboard: Initial 1.25 MB | Lazy 450 KB | Total 1.70 MB ✓ fresh
• portal: Initial 2.08 MB | Lazy 86 KB | Total 2.16 MB ✓ fresh
SHARED NX LIBRARIES & DUPLICATES
-------------------------------------------------------------
1. @nx-workspace/reports 412.50 KB (used in admin-dashboard, portal)
2. @nx-workspace/charting 195.20 KB (used in portal)
• Cross-App Repeat: exceljs repeated across 2 app deployments (1.85 MB total)

bundlecheck mcp

Model Context Protocol

Starts a native Model Context Protocol (MCP) server over standard I/O for AI coding assistants (Claude Code, Antigravity, Cursor) to inspect bundles, trace dependency chains, and enforce budgets directly inside agent tool loops.

# Register with Claude Code CLI (stdio protocol):
$ claude mcp add bundlecheck -- bundlecheck mcp
# Stdio server starts quietly and exchanges JSON-RPC 2.0 messages with client:
{"jsonrpc":"2.0","method":"tools/list"} → 6 tools available
✓ Tools: bundle_summary, bundle_why, bundle_suggest, bundle_check, bundle_measure, workspace_summary

Configuration (.bundlecheck.yml)

Persist project-wide size budgets and optimization rules in your repository root: 

# .bundlecheck.yml
budgets:
  initial_js_max: 250kb
  total_max: 1.5mb
  max_delta_increase: 50kb

rules:
  disallow_packages:
    - moment
    - lodash

GitHub Actions Integration

Drop bundlecheck directly into your GitHub Actions workflow to post automated PR comments with delta summaries and fail oversized changes. Use the entry input to scope analysis and budget enforcement to a specific entrypoint (e.g. src/main.ts or main-*.js): 

name: Bundle Size Budget Check
on: [pull_request]

jobs:
  bundlecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      
      - run: npm ci
      - run: npx ng build --stats-json
      
      - name: Run bundlecheck CI
        uses: sonuKumar03/bundlecheck@v0.6.1
        with:
          stats: dist/my-app/stats.json
          entry: src/main.ts
          max-initial: '250kb'
          post-comment: true
Agentic Architecture

AI Agents & Model Context Protocol (MCP)

Give your coding agent a measured bundle optimization loop: baseline → diagnose → trace → edit → rebuild/test → measure → gate. The Agent Skill supplies the reasoning workflow, MCP is the preferred structured interface when available, and CLI JSON is the universal fallback.

Available MCP Tools (bundlecheck mcp)
bundle_summary Inspection

Initial vs lazy JS totals, Gzip wire estimations, and top npm package contributors with optional path, project, and substring filters.

bundle_why Tracer

BFS import graph tracer revealing static and dynamic chains from entrypoints to any target library or source module.

bundle_suggest Advisor

Generates prioritized optimization recommendations for heavy packages, eager components, and duplicate libraries with potential byte savings.

bundle_check Guard

Evaluates size budgets (max initial, max total) and enforces disallowed package policies to prevent unapproved dependencies.

bundle_measure Delta

Calculates signed byte movements against saved baseline snapshots with configurable regression limits (e.g. max initial delta).

workspace_summary Monorepo

Inspects Nx monorepos, comparing multi-app sizes, shared library contributions, repeated cross-app dependencies, and build freshness.
